# SQL Agent Backend

This service exposes the SQL analysis graph over HTTP. Start it from the repository root so it can load the root `.env` file and backend source modules.

## 1. Install dependencies

From the repository root, run:

```powershell
uv sync --no-install-project
```

The project dependencies are installed into `.venv`. `--no-install-project` skips building the root package; the backend is loaded directly from `backend/src` when Uvicorn starts.

## 2. Configure environment

Set these values in the repository-root `.env` file before starting the service:

| Variable | Used for |
| --- | --- |
| `APP_API_KEY` | Authenticates incoming API requests. |
| `OPENAI_API_KEY` | Authenticates model requests. |
| `TYPESAFE_API_KEY` | Authenticates the SQL safety and correctness classifier. |
| `DB_ENGINE` | Identifies the database engine used in schema context. |
| `DB_HOST` | Database host name or address. |
| `DB_PORT` | Database port. |
| `DB_NAME` | Database name. |
| `DB_USERNAME` | Database user. |
| `DB_PWD` | Database password. |

Do not commit `.env` or put these secrets in source code.

## 3. Start the API

From the repository root, run:

```powershell
$env:PYTHONPATH = "backend/src"
.\.venv\Scripts\python.exe -m uvicorn sql_agent.api:app --app-dir backend/src --reload --host 127.0.0.1 --port 8000
```

The local API base URL is `http://127.0.0.1:8000`. Interactive API documentation is available at `http://127.0.0.1:8000/docs`.

## 4. Authenticate requests

`APP_API_KEY` - use random uuid as key and store in .env

Every API route requires the configured `APP_API_KEY` in the `X-API-Key` header. The server compares the supplied key to the environment value; it never returns the key in a response.

`GET /api/health` checks that the service is running. It also requires the API key:

```http
GET /api/health
X-API-Key: your-app-api-key
```

## 5. Submit a question

Send a JSON body to `POST /api/chat`. Questions are trimmed, must not be empty, and cannot exceed 2,000 characters.

```http
POST /api/chat
Content-Type: application/json
X-API-Key: your-app-api-key

{
  "question": "What is the total amount generated by each payment method?"
}
```

## 6. Agent processing flow

1. The API validates the question and initializes the agent state.
2. The graph curates the wording and records the original human question and assistant message history.
3. The graph connects to the configured database and extracts table, column, and sample-row context.
4. The SQL generator creates a read-only `SELECT` query. Requests to modify data or schema should return `INVALID_QUERY`.
5. The generated query is checked for safety. Unsafe queries bypass database execution and are sent to the final-answer step for a read-only limitation response.
6. Safe queries are checked for whether they answer the question. Incorrect queries may be regenerated, with at most two SQL-generation attempts.
7. A query that passes validation is executed, and the final-answer model summarizes the result. Comparison answers are requested as Markdown tables with a brief, data-supported takeaway.
8. The API returns the answer, SQL, query result string, curated question, safety classification, SQL type, and normalized messages.

## 7. Response shape

Successful `POST /api/chat` responses have this shape:

```json
{
  "answer": "The total amount by payment method is ...",
  "sql_query": "SELECT payment_method, SUM(amount) FROM payments GROUP BY payment_method;",
  "query_results": "[('card', 123.45)]",
  "curated_question": "What is the total amount for each payment method?",
  "is_safe": 0.98,
  "sql_type": "Its Data query language",
  "messages": [
    {"role": "human", "content": "What is the total amount by payment method?"},
    {"role": "ai", "content": "What is the total amount for each payment method?"},
    {"role": "ai", "content": "SELECT payment_method, SUM(amount) FROM payments GROUP BY payment_method;"},
    {"role": "ai", "content": "The total amount by payment method is ..."}
  ]
}
```

`query_results` is currently a string representation of the database rows. Message `role` values are `human` or `ai`.

## Errors

- `401 Unauthorized`: API key is missing or invalid.
- `422 Unprocessable Entity`: request body is invalid, or the question is empty or too long.
- `502 Bad Gateway`: the agent could not complete the request.
- `503 Service Unavailable`: `APP_API_KEY` is not configured.
